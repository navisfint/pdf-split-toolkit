## 二、目录错误处理策略：标记 + 继续切分

按轩的决策（「能做到有效切分那完全可以做，标记好就行」），**不再"遇错即停"**，
改为对目录异常做分类处理，能切的都切出来。

### 两类目录异常

**A. 重复登记行 → 跳过不产出（已在文件序号上留空）**

| 卷宗 | 序号 | 题名 | 目录页码 | 判定依据 |
|---|---|---|---|---|
| 60 | **12** | 砂浆试模核查记录表 | 93 | 与 #14 同页码/同物理页；正文实测 93 页处顶部是「混凝土试模」 |
| 60 | **13** | 砂浆试模核查记录表 | 111 | 与 #15 同页码/同物理页 |

依据（原文与实测）：
- 目录原图确印 **#14=93、#15=111**，与 **#12=93、#13=111** 完全重复 → 纸质目录抄写串行
- 逐页 OCR 实测：砂浆试模占物理 **79~96**（3 组 × 6 页，设备号 DH-HS-017），
  混凝土试模从物理 **97** 开始（设备号 DH-HS-016）
- 即 **93 页处实物是混凝土试模**，与 #14 题名匹配 → 保留 #14，跳过 #12/#13

**B. 页码抄错但可修复 → 正常切出 + `_待核` 标记**

| 卷宗 | 序号 | 题名 | 目录页码 | 修正结果 |
|---|---|---|---|---|
| 51 | **52** | 示例仪器校准证书 | 181（倒退）| → 页码 189（物理 196~200）|

按正文连续性推定：#51 末页 188，故 #52 从 189 起；#53 声明 194 起，故 #52 到 193 止。

### 60 号为什么是 16 个而不是 18 个

目录 18 条中，#12/#13 是同一份实物的重复登记，**实物不存在第二份**，
因此正确产出是 **16 个 PDF**。文件名保留原始序号（001~011、014~018），
中间空出的 012、013 即为被跳过的重复行，便于与目录逐行对照。

## 三、技术实现（已跑通的全链路）

```
① 目录解析    parse_toc_all.py     → toc_{tag}.json
② 页码抽样    split_main.py 内     → 求分段 offset
③ 锚点定位    局部最近邻 offset     → 预测物理页
④ 重复判重    同物理页且序号在后     → 跳过前一条
⑤ 边界计算    [起始锚点, 下一锚点-1]
⑥ 拆分输出    PyMuPDF 切片         → output/{卷宗名}/
⑦ 复核清单    report.py            → 拆分报告.md + 异常清单.csv
⑧ 质量验证    verify_by_pnmap.py   → 逐条核对页码
```

### 四个关键技术点

**1. OCR 必须关闭「文档方向分类」**
```python
PaddleOCR(use_doc_orientation_classify=False, use_doc_unwarping=False, ...)
```
否则「稀疏表格页」（只有 1 行数据 + 大量空行）会被误判为旋转 180°，整页坐标翻乱。
67 号 p3、113 号都踩过这个坑。

**2. 页码偏移是分段的**
- 67/66/113 号：offset 恒为 3
- **51 号：offset 前段=5，后段=7**（中途插入 2 页无页码内容）
- **60 号：物理 96 插入 1 页 → offset 从 3 变 4**
→ 用「**局部最近邻 offset**」预测，天然处理分段，比全局 offset 稳健。

**3. 预测值为主，OCR 确认只作标记**
实测 OCR 单点识别会把页脚英文（`Add`/`EMAIL`/`ddr`）或日期误裁进页码框，
导致确认值不是数字。但**预测物理页仍然正确**。
所以：OCR 确认失败 → 标记 `UNCONFIRMED`，**不改锚点值**。
（51 号 53 条里有 13 条属此情况，切分全部正确。）

**4. 全量页码映射（pnmap）可免 OCR 复跑**
`build_pnmap.py` 一次扫描落盘 `pnmap_{tag}.json`（物理页→页码），
后续 `split_main.py` 自动优先查表，**复跑从 10 分钟降到秒级**。

## 六、复现方式

```bash
cd scripts
python parse_toc_all.py            # ① 解析五份目录（约 13 分钟）
```
