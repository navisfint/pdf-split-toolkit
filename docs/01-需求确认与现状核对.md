## 一、先说结论：需求里有 3 处与实际不符

| 编号 | 需求原文假设 | 实测事实 | 影响 |
|---|---|---|---|
| **①** | 页码是「手打/手写」，位置不定（左下/左中/右） | **页码全部是打印体**，字体规整统一；**手写的是"检测/审核/批准"签名**，不是页码 | 不需要手写 OCR 模型，技术路线可大幅简化，准确率从"看运气"变成"可保证" |
| **②** | 正文底部只有页码一个数字 | 部分页底部**同时存在两个数字**：证书自带的「第 X 页 共 Y 页」 + 档案连续页码 | 必须区分"页脚编号"和"档案页码"，否则会误识别 |
| **③** | 漏写页码是普遍现象，需要靠连续性推断补全 | 抽样 12 页 + 首尾页，**页码 100% 连续，未发现漏写** | 补全逻辑仍要写（留作兜底），但工作量下降 |

**为什么这个判断重要**：需求描述听起来像"高难度手写 OCR 项目"，实际是"低难度打印体 OCR + 规则引擎"。这直接决定报价、周期和风险。

## 二、文档真实结构（已逐页核实）

### 2.1 页面构成

以 51 号为例（204 页）：

```
物理 p1            封面（牛皮纸色，含档号/项目名/立卷单位，无页码）
物理 p2 ~ p5       卷内目录（4 页表格，共 53 行条目）
物理 p6            正文第 1 页  → 底部页码 «1»  → 物理6 - 5 = 1
物理 p7            正文第 2 页  → 底部页码 «2»
   …
物理 p202          正文第 195 页 → 底部页码 «195»  → 物理202 - 7 = 195
物理 p203 ~ p204   封底（无页码）
```

**恒定关系（关键）**：

```
档案页码 = 物理页序 − 前置页数（封面 + 目录页数）
51 号：前置 = 5（1 封面 + 4 目录）  →  页码 = 物理 − 5
67 号：前置 = 3（1 封面 + 1 目录）  →  页码 = 物理 − 3
```

不同卷宗前置页数不同（取决于目录多少页），**不能写死**，必须自动探测。

### 2.2 每页物理规格
- **单页单图**，图像规格统一 `2480 × 3507 px`（300dpi A4 扫描件）
- **零文字层**（`textlen=0`），无法直接提取文本，必须 OCR 或图像处理
- 页面朝向：51 号有 1 页 `rotation=180`（物理 p5），其余正常；67 号全部正常

### 2.3 页码实物样式（关键证据）

**样式 A（主流，左下角）** — 页码紧贴横线下方，字号约正文 2 倍：
```
────────────────────────────────────
 2                  未经授权，不得部分复印本证书。
       Don't reproduce this certificate partly unless ...
```
（物理 p7，页码在**左下**）

**样式 B（右下角）** — 证书首页，页码在**右下**：
```
地址：北京市房山区窦店镇…            电话：010-61226943/…
                                    1
```
（物理 p6，页码在**右下**）

**样式 C（双数字干扰）** — 蓝底水印的第三方机构证书：
```
地址：云南省昆明…                    第 1 页 共 3 页   46
                                     Page  Of
```
（物理 p51，右下角**两个数字**：页脚编号 1/3，档案页码 46）

**样式 D（手写签名干扰）** — 签名区紧邻页码：
```
检测： 郭利书  审核： 小中  批准： 张泉   日期： 2021年07月11日    38
```
（物理 p41，页码 38 在**右下**，左侧全是手写签名）

### 2.4 目录页码的真实异常（已定位）

51 号目录末段实测：

| 序号 | 页码 | 判定 |
|---|---|---|
| 49 | 182 | 正常 |
| 50 | 185 | 正常 |
| 51 | 188 | 正常 |
| **52** | **181** | ⚠️ **倒退**（应为 ~191）——**需求"难点4"确实存在** |
| **53** | **194~196** | ⚠️ **区间格式**（一份文件跨 3 页），程序需支持解析 |

## 二·补 页码的精确几何位置（OCR 实测，最关键）

用 PaddleOCR 在全页尺度实测，页码归一化坐标（51 号物理 p10，真值 5）：

```
x0/W=0.005   y0/H=0.979   x1/W=0.035   y1/H=1.000
```

再叠加视觉核对（页面 80%~100% 条带放大），真实版面是：

```
┌────────────────────────────────────┐
│ …正文/附注条款…                     │  ~80%
│ ─────────────────────────  ← 横线   │  ~91%
│ 2         未经授权，不得部分复印…    │  ~92-95% ★页码与页脚文字同排
│           Don't reproduce…          │
│ EMAIL: …        邮编（Post）：102402 │  ~97%
│ 地址：…         电话（Tel）：…       │
└────────────────────────────────────┘  100%
```

**结论 1**：页码在**页面高度 88%~95% 区间**，位置随模板变化（左下/右下）。
**结论 2（最难）**：页码**与页脚文字处于同一水平带**——不是"空白底部一个孤立数字"，而是"页脚文字行首/行尾多出一个大字数字"。
**结论 3**：页码字号约为页脚文字 **2~2.5 倍**，且笔画单独成块、不与文字相连——这是最重要的可利用特征。

### OCR 实测准确率（15 个已知样本）

| 结果 | 数量 | 说明 |
|---|---|---|
| ✅ 正确识别 | 5 | `5`(0.999) `195`(1.0) `189`(1.0) 等，均为**未被裁切、无干扰**的页 |
| ❌ 完全漏检 | 8 | 页码被条带边界裁掉，或检测框未覆盖边缘 |
| ❌ 误识别 | 2 | 88→`28`(0.462)、83→乱码 |

**通用 OCR 直接扫底部条带，准确率约 40%，不可用。** 但成功案例证明：**只要页码完整进入视野且无干扰，识别置信度可达 1.0**。瓶颈在"检测/定位"，不在"识别"。

→ **技术路线修正**：把"定位"和"识别"解耦。用图像处理精确定位页码小图，再对它做单字符识别。

## 二·补2 目录解析实测（五份样本全部通过）

用 PaddleOCR 对五份卷宗的目录页做表格重建（锚点法：序号列为锚，纵向分区归属）。
**踩坑记录**：PaddleOCR 默认开启「文档方向分类」，会把「稀疏表格页」（只有一个数据行、
大量空行的页）误判为旋转 180°，导致整页 OCR 坐标翻转、序号/页码错位。
**必须显式设置 `use_doc_orientation_classify=False`**，否则 67 号 p3、113 号会解析失败。

| 卷宗 | 目录页 | 解析行数 | 结果 |
|---|---|---|---|
| 51 | p2~p5（4页） | **53** | ✅ 全对 |
| 60 | p2~p3（2页） | **18** | ✅ 全对 |
| 66 | p2~p3（2页） | **17** | ✅ 全对 |
| 67 | p2~p3（2页） | **16** | ✅ 全对 |
| 113 | p2~p3（2页） | **17** | ✅ 全对 |

页码列解析需支持两种格式：单值 `"7"` 与区间 `"194~196"`（实测 51 号 #53、60 号 #18、
66 号 #17、67 号 #16、113 号 #17 均为区间）。

### 目录页码错误的真实性质（已用原图确认）

**关键结论：目录页码的"倒退"是原始纸质目录本身的登记错误，不是 OCR 误识。**

- **51 号**：#51=188 → **#52=181**（原图上写的就是 181，应为 ~191）→ #53=194~196
- **60 号**：#13=111 → **#14=93**（与 #12 的 93 重复）、**#15=111**（与 #13 重复）
  - 真实原因：混凝土试模系列页码被误抄成了砂浆试模系列的页码
  - 正确序列应为 93 → 111 → 129 → 147 → 166~182（#14~#18 为等差 18 页间隔）

→ 已逐字核对**原件扫描图**，确认是**人为抄写错误**。这决定了处理策略：
按客户决策「遇错即停」，程序会在检测到倒退时停止该行及之后的输出（不自动猜测修正）。

## 二·补3 页码映射与锚点定位（核心算法已验证）

**不需要逐页识别全部页码。** 实测建立了两条可靠规律：

### 规律 1：分段恒定偏移

```
档案页码 = 物理页序 − offset     （offset 在一段内恒定）
67 号实测：offset = 3，抽样 40 页中 37 页投票一致
```

**求 offset 的方法**：抽样若干页（步长 = 总页数/40），对每页识别页码，
`offset = 物理页 − 页码`，取众数（多数表决）。OCR 单页误识率约 20%~30%，
但**众数投票对个别错误免疫**（37/40 一致即为可靠）。

### 规律 2：锚点预测 + 单点验证

```
目录条目起始页码 sp  →  预测物理页 = sp + offset  →  只 OCR 该页验证
```

**67 号实测：16 个目录锚点全部命中，16/16 ✅**

| 序号 | 目录页码 | 预测物理页 | 实际识别 | 结果 |
|---|---|---|---|---|
| 1 | 1 | 4 | `1` | ✅ |
| 2 | 7 | 10 | `7` | ✅ |
| … | … | … | … | ✅ |
| 16 | 117 | 120 | `117` | ✅ |

**这条链路是"以正文页码为准"的正确落地方式**：目录页码只用来"找位置"，
最终以正文页码的实测结果为准，两者交叉验证。

## 四、拟定技术方案（基于实测修正）

需求原方案的"手写 OCR"环节**可以砍掉**。修正后：

```
① 前置页探测   → 识别封面/目录页边界，算出「前置页数」offset
② 目录解析     → 表格识别提取 (序号, 题名, 起始页码)；解析器支持 "194~196" 区间格式
③ 页码识别     → 裁切每页底部条带 → 打印体数字识别（模板匹配 + OCR 兜底）
                 └ 关键：排除 "第X页共Y页" 干扰、排除手写签名干扰
④ 映射构建     → 物理页 ↔ 档案页码 映射表
⑤ 连续性校验   → 检测缺号/重号，缺失处标记 UNCERTAIN
⑥ 目录对齐     → 目录起始页码 → 物理页；检测页码倒退
⑦ 拆分输出     → PyMuPDF 按页区间切割，输出 PDF + 异常清单 CSV
```

**与需求原方案的差异**：删掉手写 OCR（改用打印体识别，更快更准），新增"前置页探测"和"干扰排除"两个必要环节。

## 五、风险评估

| 风险 | 等级 | 说明 | 对策 |
|---|---|---|---|
| 多机构模板混排 | **高** | 已发现 ≥3 种证书模板，页码位置/字体不同 | 页码识别按"底部条带全扫描"而非固定坐标 |
| 页脚编号干扰 | **高** | "第X页共Y页"与档案页码并存 | 多数字候选时，用连续性约束择优 |
| 目录页码本身有错 | 中 | 已实测到倒退 | 检测 + 标记，不自动修正 |
| 前置页数不固定 | 中 | 51 号=5，67 号=3 | 自动探测，不硬编码 |
| 页面旋转 | 低 | 51 号有 1 页旋转 180° | 渲染时自动纠正 |
